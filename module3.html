The Analog Final Frontier

Digital EDA automation has made remarkable progress — tools like OpenROAD can complete place-and-route with minimal human intervention. But analog design remains fundamentally harder to automate, for several deep reasons.

〰
Continuous-Valued Signals
Unlike digital (1 or 0), analog signals have infinite precision. Performance specs like Gain-Bandwidth Product, PSRR, and phase margin require continuous optimization over a multidimensional design space.
⚠
Layout Parasitics
Performance is inseparable from physical implementation. A 10fF parasitic capacitance from poor layout can collapse gain by 6dB. Agents must reason about both schematic and physical domains simultaneously.
⏱
Slow Simulation Feedback
A full SPICE simulation across all process corners can take hours per run. This makes iterative RL-style training prohibitively expensive and demands clever approximation strategies.
📊
Non-Functional Specs
Metrics like stability (phase margin > 45°), noise (input-referred noise floor), and linearity (THD) cannot be expressed as simple binary pass/fail — they require nuanced interpretation.
💜 Why This Matters for Agent Design

These challenges force analog EDA agents to be fundamentally different from digital ones. They need: multimodal perception (reading waveforms), stratified memory (remembering cross-task insights), and physics-grounded reasoning (understanding parasitics cause and effect). The four systems in this module each address a different facet of this challenge.

💻

AnalogCoder & AnalogCoder-Pro

AnalogCoder is an AAAI 2025 Oral paper that reconceptualizes analog circuit design as a code generation problem. Instead of directly predicting SPICE netlists (which have complex syntax and no abstraction), it generates Python code using PySpice — a more natural medium for LLMs.

Design as Python Code Generation

The core insight: LLMs are much better at generating Python code than raw SPICE syntax. PySpice provides a Pythonic API to SPICE, so AnalogCoder:

  1. Receives a natural language spec: "Design a 2-stage Miller OTA with 60dB DC gain, GBW > 10MHz, PM > 60°"
  2. Generates Python code using PySpice to describe the circuit netlist
  3. Executes the code to produce a SPICE netlist
  4. Runs Ngspice simulation and captures results
  5. Analyzes results and refines the code if specs are not met
✓ Key Advantage

Python code is easier to modify incrementally than SPICE netlist syntax. When an agent needs to change a transistor W/L ratio, it modifies a Python variable — not a raw text substitution in a netlist file.

Training-Free Approach (Zero-Shot)

AnalogCoder is explicitly training-free — it uses foundation LLMs (GPT-4, Claude) directly with carefully engineered prompts, rather than requiring expensive fine-tuning on hardware data.

This is critical because:

  • High-quality labeled analog design data is extremely scarce
  • Fine-tuning requires significant compute and expertise
  • Training-free methods can immediately leverage new foundation models
📚
Circuit Function Library
A curated library of circuit templates (current mirrors, differential pairs, cascode stages) is provided as context. The LLM assembles these building blocks rather than generating circuits from scratch.
🔄
Feedback Loop
Simulation results (gain, bandwidth, phase margin) are fed back to the LLM as text, which then generates modified Python code. This creates a closed-loop design optimization cycle.

AnalogCoder-Pro: Multimodal Waveform Analysis

AnalogCoder-Pro extends the base system with multimodal perception: instead of reading simulation results as text numbers, the agent visually analyzes waveform plots using a vision-capable LLM.

👁
Visual Analysis
The agent generates a .png of the Bode plot (gain/phase vs. frequency). A multimodal LLM (Gemini 3 Pro or Claude 4.5 Vision) analyzes the image, identifying visual patterns like gain peaking (instability indicator) or bandwidth roll-off too early.
🎯
Structured Insight
After image analysis, the LLM produces structured feedback: "Phase margin is ~35° at GBW — below the 60° target. Recommend increasing Miller capacitor by 2× to add phase lead."
Python — Multimodal Waveform Analysis 
import base64
import matplotlib.pyplot as plt
import numpy as np
from langchain_anthropic import ChatAnthropic
from langchain_core.messages import HumanMessage

def analyze_bode_plot_visually(frequencies, gain_dB, phase_deg):
    """Generate Bode plot and analyze it with a vision LLM."""
    
    # Generate the Bode plot
    fig, (ax1, ax2) = plt.subplots(2, 1, figsize=(10, 8))
    ax1.semilogx(frequencies, gain_dB, 'b-', linewidth=2)
    ax1.set_ylabel('Gain (dB)')
    ax1.set_title('Bode Plot — Gain')
    ax1.grid(True, which='both', alpha=0.3)
    ax1.axhline(y=0, color='r', linestyle='--', alpha=0.5, label='0 dB')
    
    ax2.semilogx(frequencies, phase_deg, 'r-', linewidth=2)
    ax2.set_ylabel('Phase (degrees)')
    ax2.set_xlabel('Frequency (Hz)')
    ax2.set_title('Bode Plot — Phase')
    ax2.grid(True, which='both', alpha=0.3)
    ax2.axhline(y=-180, color='k', linestyle='--', alpha=0.5, label='-180°')
    
    plt.tight_layout()
    plt.savefig('/tmp/bode_plot.png', dpi=150, bbox_inches='tight')
    plt.close()
    
    # Encode as base64 for the vision API
    with open('/tmp/bode_plot.png', 'rb') as f:
        image_data = base64.b64encode(f.read()).decode('utf-8')
    
    # Send to vision-capable LLM for analysis
    claude = ChatAnthropic(model="claude-opus-4-5")
    message = HumanMessage(content=[
        {
            "type": "image",
            "source": {"type": "base64", "media_type": "image/png", "data": image_data}
        },
        {
            "type": "text",
            "text": """Analyze this Bode plot for an operational transconductance amplifier (OTA).
            
            Identify:
            1. DC gain (dB) — read the flat region value
            2. Gain-Bandwidth Product (GBW) — frequency where gain crosses 0dB
            3. Phase margin — phase at GBW frequency relative to -180°
            4. Any instability indicators (gain peaking, phase dropping below -180° before GBW)
            5. Specific design changes to improve phase margin if below 60°
            
            Provide structured JSON output."""
        }
    ])
    
    analysis = claude.invoke([message])
    return analysis.content

Python — AnalogCoder Netlist Generation 
from PySpice.Spice.Netlist import Circuit
from PySpice.Unit import *
from langchain_openai import ChatOpenAI

# AnalogCoder generates Python code like this:
def design_two_stage_ota(spec: dict) -> str:
    """Generated by AnalogCoder — 2-stage Miller OTA."""
    
    circuit = Circuit('Two-Stage Miller OTA')
    
    # Supply
    circuit.V('dd', 'VDD', circuit.gnd, 1.8@u_V)
    
    # Bias current
    circuit.I('bias', 'VDD', 'IBIAS', spec['Ibias']@u_µA)
    
    # Input differential pair (M1, M2)
    circuit.MOSFET('M1', 'vout1', 'vinp', 'vs', 'vs',
                   model='NMOS_SKY130', w=spec['W1']@u_µm, l=spec['L1']@u_µm)
    circuit.MOSFET('M2', 'vout1b', 'vinn', 'vs', 'vs',
                   model='NMOS_SKY130', w=spec['W1']@u_µm, l=spec['L1']@u_µm)
    
    # Tail current source (M5)
    circuit.MOSFET('M5', 'vs', 'IBIAS', circuit.gnd, circuit.gnd,
                   model='NMOS_SKY130', w=spec['W5']@u_µm, l=spec['L5']@u_µm)
    
    # Load current mirror (M3, M4) 
    circuit.MOSFET('M3', 'vout1', 'vout1', 'VDD', 'VDD',
                   model='PMOS_SKY130', w=spec['W3']@u_µm, l=spec['L3']@u_µm)
    circuit.MOSFET('M4', 'vout1b', 'vout1', 'VDD', 'VDD',
                   model='PMOS_SKY130', w=spec['W3']@u_µm, l=spec['L3']@u_µm)
    
    # Second stage (M6)
    circuit.MOSFET('M6', 'vout', 'vout1b', circuit.gnd, circuit.gnd,
                   model='NMOS_SKY130', w=spec['W6']@u_µm, l=spec['L6']@u_µm)
    
    # Miller compensation
    circuit.C('c', 'vout', 'vout1b', spec['Cc']@u_pF)
    circuit.R('z', 'vout', 'vout1b', spec['Rz']@u_kΩ)
    
    return circuit.str()

# LLM determines specs based on requirements
llm = ChatOpenAI(model="gpt-4o")
response = llm.invoke("""Given: 60dB gain, GBW=10MHz, PM>60°, VDD=1.8V, Ibias=10µA
Determine: W1,L1,W3,L3,W5,L5,W6,L6,Cc,Rz in SKY130 PDK
Output JSON.""")

spec = parse_json(response.content)
netlist = design_two_stage_ota(spec)

AnalogSAGE: Self-Evolving Framework

AnalogSAGE (Self-Evolving Analog Generative Engine) introduces a breakthrough in agentic memory: the Stratified Memory Hierarchy. Instead of treating all agent experience uniformly, it organizes memory into three distinct layers that serve different functions.

The Stratified Memory Hierarchy

🌐
Layer 1: Evolution Memory
Scope: Cross-task insights

Stores generalizable knowledge gained across multiple design tasks. Example: "Folded-cascode topologies consistently achieve better PSRR than standard differential pairs in 1.8V designs. When PSRR > 60dB is required, start with folded-cascode."

This layer evolves continuously as the agent completes more designs, becoming an ever-richer repository of analog design wisdom.

🔍
Layer 2: Introspective Memory
Scope: Within-task failure reflections

Records what went wrong during the current design task and how it was resolved. Example: "Tried Cc=2pF → PM=32° (insufficient). Increased to 4pF → PM=58° (marginal). With Rz=1kΩ added → PM=68° ✓."

This enables the agent to avoid repeating the same failures within a single design session — critical given SPICE simulation costs.

🗜
Layer 3: Fusion Memory
Scope: Compressed reasoning traces

A compressed, dense representation of the agent's reasoning process. Strips away verbose LLM output and retains only the key causal chain: Observation → Hypothesis → Experiment → Conclusion.

Enables efficient retrieval — when facing a new design, the agent retrieves relevant compressed traces from past experience.

Python — AnalogSAGE Stratified Memory 
from dataclasses import dataclass, field
from typing import List, Optional
import json
from datetime import datetime

@dataclass
class MemoryEntry:
    content: str
    timestamp: str = field(default_factory=lambda: datetime.now().isoformat())
    embedding: Optional[List[float]] = None
    relevance_score: float = 0.0

class StratifiedMemoryHierarchy:
    """AnalogSAGE three-layer memory system."""
    
    def __init__(self, embedder):
        self.embedder = embedder
        self.evolution_memory: List[MemoryEntry] = []    # Cross-task
        self.introspective_memory: List[MemoryEntry] = [] # Within-task
        self.fusion_memory: List[MemoryEntry] = []        # Compressed traces
    
    def record_failure(self, observation: str, action: str, result: str):
        """Layer 2: Record within-task failure and recovery."""
        entry = MemoryEntry(
            content=f"TRIED: {action} | RESULT: {result} | OBS: {observation}"
        )
        entry.embedding = self.embedder.embed(entry.content)
        self.introspective_memory.append(entry)
    
    def record_cross_task_insight(self, insight: str, source_tasks: List[str]):
        """Layer 1: Record generalizable insight from multiple tasks."""
        entry = MemoryEntry(
            content=f"INSIGHT: {insight} | SOURCE: {source_tasks}"
        )
        entry.embedding = self.embedder.embed(entry.content)
        self.evolution_memory.append(entry)
    
    def compress_and_store_trace(self, full_trace: List[dict], llm):
        """Layer 3: Compress reasoning trace for efficient retrieval."""
        trace_text = "\n".join([f"{t['step']}: {t['action']} → {t['outcome']}" 
                                 for t in full_trace])
        
        compression_prompt = f"""Compress this design reasoning trace to its essential 
        causal chain (Observation → Hypothesis → Experiment → Conclusion):
        
        {trace_text}
        
        Output a dense 3-5 sentence summary capturing only causal relationships."""
        
        compressed = llm.invoke(compression_prompt)
        entry = MemoryEntry(content=compressed.content)
        entry.embedding = self.embedder.embed(entry.content)
        self.fusion_memory.append(entry)
    
    def retrieve_relevant(self, query: str, top_k: int = 3) -> dict:
        """Retrieve relevant memories from all layers for a new design task."""
        query_embedding = self.embedder.embed(query)
        
        def cosine_sim(a, b):
            import numpy as np
            return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))
        
        # Search all layers
        results = {"evolution": [], "introspective": [], "fusion": []}
        
        for layer_name, layer in [("evolution", self.evolution_memory),
                                    ("introspective", self.introspective_memory),
                                    ("fusion", self.fusion_memory)]:
            scored = [(cosine_sim(query_embedding, e.embedding), e) 
                      for e in layer if e.embedding]
            scored.sort(reverse=True)
            results[layer_name] = [e.content for _, e in scored[:top_k]]
        
        return results

GENIE-ASI: Subcircuit Identification (Sony AI)

GENIE-ASI (Generative Netlist Inspector for Analog Subcircuit Identification) is a training-free system from Sony AI that addresses a specific but critical problem: automatically identifying functional blocks within a complex SPICE netlist.

🔵 The Problem GENIE-ASI Solves

A modern analog IC can have hundreds of transistors in a single SPICE netlist. Before any optimization agent can operate, it needs to know where the current mirrors are, where the differential pairs are, and what each subcircuit does. GENIE-ASI automates this structural analysis.

📝
Training-Free Method
Like AnalogCoder, GENIE-ASI requires no specialized training. It uses few-shot examples of known subcircuits (current mirrors, diff pairs, cascode structures) provided as context to identify patterns in unseen netlists.
🐍
Python Code Generation
GENIE-ASI generates Python code to parse the SPICE netlist and identify functional blocks. This is more reliable than direct LLM text matching — the code can inspect graph topology rigorously.
🧩
Generalization
Works on unseen netlists — including proprietary designs the system has never encountered. The structural patterns of analog circuits (gate-drain connections, symmetry) are universal.
Python — GENIE-ASI Subcircuit Identification 
from langchain_openai import ChatOpenAI
import networkx as nx
import re

CURRENT_MIRROR_EXAMPLE = """
# Current mirror: gate-drain of M_ref connected, same gate drives M_out
# Pattern: gate(M_ref) == drain(M_ref) AND gate(M_ref) == gate(M_out)
"""

DIFF_PAIR_EXAMPLE = """
# Differential pair: two matched devices share a tail node
# Pattern: source(M1) == source(M2) == tail_node, symmetric
"""

def genie_identify_subcircuits(spice_netlist: str, llm: ChatOpenAI) -> dict:
    """GENIE-ASI: Generate Python code to identify subcircuits."""
    
    prompt = f"""You are an analog IC expert. Generate Python code using networkx
to identify functional subcircuits in the SPICE netlist below.

Few-shot examples of what to detect:
{CURRENT_MIRROR_EXAMPLE}
{DIFF_PAIR_EXAMPLE}

SPICE Netlist:
{spice_netlist}

Generate Python code that:
1. Parses the netlist into a networkx directed graph
2. Identifies current mirrors, differential pairs, cascode structures
3. Returns a dict: {{subcircuit_type: [transistor_names]}}

Output only executable Python code."""
    
    code = llm.invoke(prompt).content
    
    # Execute the generated identification code safely
    safe_globals = {"nx": nx, "re": re, "netlist": spice_netlist}
    exec(code, safe_globals)
    
    return safe_globals.get("identified_subcircuits", {})

# Example usage
netlist = """
M1 vout1 vinp vs vss NMOS W=2u L=0.18u
M2 vout2 vinn vs vss NMOS W=2u L=0.18u  
M3 vout1 vout1 vdd vdd PMOS W=4u L=0.18u
M4 vout2 vout1 vdd vdd PMOS W=4u L=0.18u
M5 vs ibias vss vss NMOS W=4u L=0.18u
"""

llm = ChatOpenAI(model="gpt-4o")
subcircuits = genie_identify_subcircuits(netlist, llm)
# Returns: {"differential_pair": ["M1", "M2"], "current_mirror": ["M3", "M4"], 
#           "tail_current": ["M5"]}

Schemato: Netlist → Schematic Visualization

Schemato is a fine-tuned Llama 3.1-8B model that converts raw SPICE netlists into human-readable LTSpice schematic files (.asc). It bridges the critical visualization gap in analog design workflows.

⚠ The Visualization Problem

When an agent generates a SPICE netlist, neither the engineer nor other agents can quickly verify its correctness — raw netlist text is extremely hard to read for complex circuits. Schemato solves this by converting the text representation to a visual schematic that engineers can immediately understand and validate.

🧠
Fine-Tuned Llama 3.1-8B
Trained on paired (SPICE netlist, LTSpice .asc) examples. The model learns the mapping from SPICE syntax to LTSpice's proprietary schematic format with correct component placement and wiring.
🔗
Human-in-the-Loop Bridge
Enables the Human-in-the-Loop design pattern: the agent generates a netlist, Schemato converts it to a schematic, the engineer visually approves it, then the agent continues with physical design.
✅
LVS Pre-Check
The generated schematic can also feed into LVS (Layout vs. Schematic) checks, providing a reference schematic without requiring manual re-entry by the design engineer.
Python — Schemato Integration 
from langchain_community.llms import Ollama

# Schemato: fine-tuned Llama 3.1-8B for SPICE→LTSpice conversion
schemato = Ollama(model="schemato-llama3.1-8b")

def convert_spice_to_ltspice(spice_netlist: str) -> str:
    """Convert SPICE netlist to LTSpice .asc schematic format."""
    
    prompt = f"""Convert the following SPICE netlist to an LTSpice schematic (.asc format).
    
Place components with proper spatial layout:
- Differential pair transistors symmetrically
- Supply rails at top, ground at bottom
- Input ports on left, output on right

SPICE Input:
{spice_netlist}

Generate the complete .asc file content."""
    
    asc_content = schemato.invoke(prompt)
    
    # Save the schematic
    with open("/tmp/generated_schematic.asc", "w") as f:
        f.write(asc_content)
    
    return asc_content
