Mastering Model Context Protocol (MCP)

The Model Context Protocol (MCP) is rapidly becoming the industry standard for how AI models interact with external tools and resources. It has been called the "USB-C of AI" — a universal connector that standardizes how models talk to external tools, eliminating the need for custom glue code.

🔵 Why MCP Matters for EDA

Before MCP, every EDA tool integration required custom code: a custom Ngspice adapter, a custom OpenROAD bridge, a custom Cadence connector. With MCP, you implement one standard interface and every MCP-compatible model (Claude, GPT, Gemini) can immediately use all your EDA tools.

MCP Architecture

💻
MCP Host
The application managing the LLM and orchestrating MCP connections. Examples: Claude Desktop, custom LangGraph workflow, an agentic EDA platform. The host maintains the conversation context and decides which MCP servers to connect to.
🖥
MCP Server
Exposes capabilities to the model via three primitives:
  • Tools: Functions the model can call
  • Resources: Data the model can read
  • Prompts: Template prompts to guide reasoning
📡
MCP Protocol
Communication happens over JSON-RPC 2.0 via stdio (local) or HTTP+SSE (remote). The model sends tool call requests; the MCP server executes them and returns structured results.

Building an Ngspice MCP Server

The Mastery Step from the course report is to implement an MCP server for a simulator (Ngspice) that allows agents to pull simulation results directly without custom glue code. Here's the complete implementation:

Python — ngspice_mcp_server.py 
#!/usr/bin/env python3
"""Ngspice MCP Server — EDA simulation via standard MCP interface."""

from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp.types import Tool, TextContent, Resource
import asyncio
import json

server = Server("ngspice-eda-server")

@server.list_tools()
async def list_tools() -> list[Tool]:
    """Expose available simulation tools."""
    return [
        Tool(
            name="run_ngspice_sim",
            description="Run an Ngspice SPICE simulation and return results",
            inputSchema={
                "type": "object",
                "properties": {
                    "netlist": {"type": "string", "description": "SPICE netlist content"},
                    "analysis_type": {
                        "type": "string",
                        "enum": ["dc", "ac", "transient", "noise"],
                        "description": "Type of SPICE analysis"
                    },
                    "output_variables": {
                        "type": "array",
                        "items": {"type": "string"},
                        "description": "Variables to capture (e.g., ['V(out)', 'I(R1)'])"
                    }
                },
                "required": ["netlist", "analysis_type"]
            }
        ),
        Tool(
            name="get_bode_plot",
            description="Run AC analysis and return Bode plot data (gain and phase vs frequency)",
            inputSchema={
                "type": "object",
                "properties": {
                    "netlist": {"type": "string"},
                    "freq_start": {"type": "number", "description": "Start frequency in Hz"},
                    "freq_stop": {"type": "number", "description": "Stop frequency in Hz"},
                    "n_points": {"type": "integer", "default": 100}
                },
                "required": ["netlist", "freq_start", "freq_stop"]
            }
        ),
        Tool(
            name="check_drc",
            description="Run Design Rule Check on a layout file",
            inputSchema={
                "type": "object",
                "properties": {
                    "layout_file": {"type": "string", "description": "Path to GDS/OASIS layout"},
                    "pdk": {"type": "string", "enum": ["sky130", "gf180", "tsmc28"]}
                },
                "required": ["layout_file", "pdk"]
            }
        )
    ]

async def main():
    async with stdio_server() as (read_stream, write_stream):
        await server.run(read_stream, write_stream, server.create_initialization_options())

@server.call_tool()
async def call_tool(name: str, arguments: dict):
    """Execute tool calls from the LLM."""
    
    if name == "run_ngspice_sim":
        netlist = arguments["netlist"]
        analysis = arguments["analysis_type"]
        outputs = arguments.get("output_variables", [])
        
        # Write netlist to temp file
        import tempfile, subprocess
        with tempfile.NamedTemporaryFile(suffix=".sp", mode="w", delete=False) as f:
            f.write(netlist)
            netlist_path = f.name
        
        # Run Ngspice in batch mode
        result = subprocess.run(
            ["ngspice", "-b", "-o", "/tmp/sim_output.txt", netlist_path],
            capture_output=True, text=True, timeout=300
        )
        
        if result.returncode != 0:
            return [TextContent(type="text", text=f"SIMULATION ERROR:\n{result.stderr}")]
        
        # Parse output
        sim_data = parse_ngspice_output("/tmp/sim_output.txt", outputs)
        
        return [TextContent(
            type="text",
            text=json.dumps({
                "status": "success",
                "analysis_type": analysis,
                "results": sim_data,
                "convergence": True
            }, indent=2)
        )]
    
    elif name == "get_bode_plot":
        # Generate Bode plot data
        netlist = arguments["netlist"]
        freq_start = arguments["freq_start"]
        freq_stop = arguments["freq_stop"]
        
        # Add AC analysis to netlist
        ac_netlist = netlist + f"""
.ac dec 20 {freq_start} {freq_stop}
.print ac V(out)
.end
"""
        bode_data = run_ac_analysis(ac_netlist)
        metrics = extract_bode_metrics(bode_data)
        
        return [TextContent(
            type="text",
            text=json.dumps({
                "gain_dB": bode_data["gain"],
                "phase_deg": bode_data["phase"],
                "frequencies": bode_data["freq"],
                "metrics": metrics

Python — Connecting MCP to LangGraph Agent 
from langchain_mcp_adapters.client import MultiServerMCPClient
from langgraph.prebuilt import create_react_agent
from langchain_anthropic import ChatAnthropic

async def create_eda_agent():
    """Create a LangGraph agent with MCP tool access."""
    
    # Connect to all MCP servers
    async with MultiServerMCPClient({
        "ngspice": {
            "command": "python",
            "args": ["ngspice_mcp_server.py"],
            "transport": "stdio"
        },
        "openroad": {
            "command": "python",
            "args": ["openroad_mcp_server.py"],
            "transport": "stdio"
        },
        "pdk": {
            "url": "http://localhost:8001/mcp",
            "transport": "sse"
        }
    }) as mcp_client:
        
        # Get all available tools from all servers
        tools = await mcp_client.get_tools()
        
        # Create a ReAct agent with these tools
        llm = ChatAnthropic(model="claude-opus-4-5")
        agent = create_react_agent(llm, tools)
        
        # Run the agent
        result = await agent.ainvoke({
            "messages": [{
                "role": "user",
                "content": """Design a 2-stage OTA with 60dB gain and GBW > 10MHz.
                Use the ngspice tools to simulate and verify your design.
                Start with an analytical initial sizing, then iterate using simulation feedback."""
            }]
        })
        
        return result

@server.read_resource()
async def read_resource(uri: str) -> str:
    """Return resource content when requested by model."""
    if uri == "pdk://sky130/transistor-models":
        with open("/pdk/sky130/models/sky130.lib") as f:
            return f.read()
    elif uri == "library://analog/circuit-templates":
        return json.dumps(load_circuit_templates())
    return ""

LangGraph: Advanced Production Patterns

Beyond the basic workflow covered in Module 1, LangGraph offers three advanced capabilities that are essential for production EDA workflows.

Persistent Checkpointing for Long-Running Workflows

EDA workflows can run for 24–48 hours. Without checkpointing, a server crash or power failure means starting from scratch. LangGraph's checkpointer saves state after every node execution.

Python — Production Checkpointing Setup 
from langgraph.checkpoint.postgres import PostgresSaver
from langgraph.checkpoint.sqlite import SqliteSaver
from psycopg import Connection

# Production: PostgreSQL-backed checkpointing (survives machine reboots)
conn_string = "postgresql://eda_agent:secret@postgres-host:5432/eda_workflows"
with Connection.connect(conn_string) as conn:
    PostgresSaver.create_tables(conn)  # One-time schema setup

checkpointer = PostgresSaver(conn)

# Development: SQLite (simpler, single-file)
checkpointer_dev = SqliteSaver.from_conn_string("./eda_checkpoint.db")

# Compile workflow with checkpointer
app = workflow.compile(checkpointer=checkpointer)

# Run with unique thread_id — enables resumption
config = {"configurable": {"thread_id": "pr-risc-v-001-20260320"}}

# First run (or resume if interrupted)
result = app.invoke(initial_state, config=config)

# Later — machine crashed, resume from checkpoint:
# Simply run again with the SAME thread_id
# LangGraph finds the last checkpoint and continues from there
result = app.invoke(None, config=config)  # None = continue from checkpoint

# Check current state without executing
state = app.get_state(config)
print(f"Last completed node: {state.next}")
print(f"Current iteration: {state.values['iteration']}")

Conditional Routing Based on PPA Results

Conditional routing is how the agent decides whether to proceed to layout or loop back for re-sizing based on simulation results.

Python — Conditional PPA Routing 
from langgraph.graph import END

def ppa_routing_logic(state: EDADesignState) -> str:
    """
    Decide the next action based on PPA results.
    Returns the name of the next node or END.
    """
    achieved = state.get("ppa_achieved", {})
    targets = state["ppa_targets"]
    iteration = state["iteration"]
    max_iter = state["max_iterations"]
    
    # Check if all PPA targets are met
    all_targets_met = all(
        achieved.get(metric, 0) >= target
        for metric, target in targets.items()
    )
    
    if all_targets_met:
        print(f"✓ All PPA targets met at iteration {iteration}")
        return "layout"  # Proceed to physical layout
    
    if iteration >= max_iter:
        print(f"✗ Max iterations ({max_iter}) reached without convergence")
        return END  # Give up
    
    # Determine which constraint is most violated
    violations = {
        k: targets[k] - achieved.get(k, 0) 
        for k in targets if achieved.get(k, 0) < targets[k]
    }
    most_violated = max(violations, key=violations.get)
    
    # Route to appropriate specialist
    if most_violated == "gain_dB":
        return "topology_selection"  # Need different topology
    elif most_violated in ["GBW_MHz", "phase_margin_deg"]:
        return "sizing"  # Just re-size
    else:
        return "sizing"  # Default: try re-sizing

# Add conditional edges
workflow.add_conditional_edges(
    "critic",
    ppa_routing_logic,
    {
        "layout": "layout",
        "sizing": "sizing",
        "topology_selection": "topology_selection",
        END: END
    }
)

Time-Travel Debugging

Time-travel debugging is one of LangGraph's most powerful features: inspect any historical state and understand exactly why the agent made each decision.

Python — Time-Travel Debugging & State Forking 
# ── Inspecting Historical States ──────────────────────────────

history = list(app.get_state_history(config))
print(f"Total workflow steps recorded: {len(history)}")

# Pretty-print the workflow trace
for i, snapshot in enumerate(reversed(history)):
    print(f"\n[Step {i+1}] Node: {snapshot.next}")
    print(f"  Iteration: {snapshot.values.get('iteration', 0)}")
    print(f"  PPA achieved: {snapshot.values.get('ppa_achieved', {})}")
    print(f"  Errors: {snapshot.values.get('errors', [])}")

# ── Understanding a Specific Failure ──────────────────────────

# Find the step where gain degraded
gain_failure_step = None
for snapshot in history:
    ppa = snapshot.values.get("ppa_achieved", {})
    if ppa.get("gain_dB", 0) < 50:  # Gain dropped below 50dB
        gain_failure_step = snapshot
        break

if gain_failure_step:
    print(f"\nGain failure occurred at node: {gain_failure_step.next}")
    print(f"Netlist at failure: {gain_failure_step.values['netlist']}")
    print(f"Topology at failure: {gain_failure_step.values['topology']}")

# ── Forking from a Past State (Alternative Approach) ──────────

# Go back to before the problematic topology was selected
good_state = history[-8]  # 8 steps back

# Modify the state to try a different topology
app.update_state(
    good_state.config,
    {
        "topology": "folded_cascode",  # Try a different topology
        "errors": [],                   # Clear accumulated errors
        "iteration": good_state.values["iteration"]  # Preserve iteration count
    },
    as_node="topology_selection"  # Tag as if topology_selection ran
)

# Resume from this forked point
new_result = app.invoke(None, good_state.config)

Human-in-the-Loop with Interrupt

Production EDA agents should pause at key decision points for human approval — especially before committing expensive operations (tapeout, 48-hour P&R run).

Python — Human Approval Gate 
# Compile with interrupt_before for human approval gates
app = workflow.compile(
    checkpointer=checkpointer,
    interrupt_before=["layout"]  # Pause before expensive layout step
)

# Run until the interrupt
result = app.invoke(initial_state, config=config)
# → Stops before "layout", saves state

# Human reviews the schematic-level results
current_state = app.get_state(config)
ppa = current_state.values["ppa_achieved"]
netlist = current_state.values["netlist"]

print("Design ready for layout:")
print(f"  Gain: {ppa['gain_dB']:.1f} dB (target: 60 dB)")
print(f"  GBW: {ppa['GBW_MHz']:.1f} MHz (target: 10 MHz)")
print(f"  Phase Margin: {ppa['phase_margin_deg']:.1f}° (target: 60°)")

# Human decision
human_approval = input("Approve for layout? (y/n): ")

if human_approval.lower() == 'y':
    # Continue the workflow
    final_result = app.invoke(None, config=config)
else:
    # Override and adjust
    app.update_state(config, {"topology": "alternative_topology"})
    final_result = app.invoke(None, config=config)

The Twelve Pillars of Production MAS

Moving from a demo prototype to a production-grade enterprise system requires implementing all twelve pillars. Skipping any one of these creates critical gaps in reliability, security, or scalability.

01
Secure Model Integration (BYOM)
Bring Your Own Model — integrate proprietary and fine-tuned models without vendor lock-in. Essential for IP-sensitive EDA environments.
02
End-to-End Observability
Every agent call, tool invocation, and state transition is logged, traced, and monitored. LangSmith for LangChain/LangGraph. Essential for debugging production failures.
03
Typed Context Engineering
All state objects use TypedDict or Pydantic schemas. Prevents "undefined" errors from unstructured agent outputs. Type-checking at workflow definition time.
04
Domain Ontology
A formal knowledge graph of EDA concepts: transistor types, circuit topologies, design rules, tool commands. Gives agents a shared vocabulary and structured knowledge.
05
Vector / Compute Tool Services
Vector databases (Pinecone, pgvector) for semantic retrieval of past designs. Compute services (Ray, Dask) for parallel simulation execution. Critical for scalable MAS.
06
Governance & Security
Role-based access control for EDA tools, encryption of proprietary netlists, audit trails for all agent actions. Mandatory for semiconductor IP protection.
07
Agent Lifecycle (CI/CD)
Version control for prompts, automated testing of agent behavior changes, staged rollouts (canary deployments) for agent updates. Treat agents like production software.
08
Operational Automation
Auto-scaling simulation compute based on queue depth, automatic retry logic for failed tool calls, SLA monitoring and alerting. Kubernetes + Argo Workflows.
09
Development Environments
Containerized EDA tool environments (Docker), mock simulators for fast testing, reproducible build systems (Nix, conda). Enable rapid iteration without tool setup friction.
10
Human-in-the-Loop UX
Approval gates before high-risk actions (tapeout, long P&R runs), design review dashboards showing agent reasoning, override mechanisms for human correction.
11
Package / Release (Docker)
All agent code, EDA tool wrappers, and MCP servers containerized as Docker images. Helm charts for Kubernetes deployment. Semantic versioning and release notes.
12
Enterprise Automation
Integration with enterprise systems: JIRA for design tracking, Confluence for documentation, Git for netlist versioning. Full enterprise IT stack compatibility.
💜 Production Readiness Assessment

Rate your current system against each pillar (0–2 points each, max 24). A score of 0–8 = prototype, 9–16 = staging, 17–24 = production-ready. Most early agentic EDA systems score 3–6 — pillars 2 (observability), 6 (governance), and 11 (Docker) are the highest-priority upgrades.
